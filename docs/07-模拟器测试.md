# 在 Android Studio 模拟器里测试

> 本机已经有一个可用的 AVD：**`Medium_Phone_API_37.0`**（1080×2400，Android 37，x86_64）。
> 本文两种方式都写过——图形界面点，或者命令行跑。

---

## 方式一：Android Studio 图形界面（推荐给你）

### 1. 装 Flutter 插件（只做一次）

**这一步不能跳过。** 本项目是 Flutter 工程，`android/` 只是宿主壳。
如果没装插件，Android Studio 会把 `android/` 当成一个普通 Gradle 工程打开，**跑不起来**。

`File → Settings → Plugins` → 搜索 **Flutter** → Install（会连带装 Dart）→ 重启 AS。

### 2. 打开工程

`File → Open` → 选择：

```
E:\pingshu
```

**注意选 `tingshu` 这一层，不要选 `tingshu\android`。**
打开后右下角会出现 "Gradle sync"，第一次同步要 3~8 分钟（要下 Gradle 9.5 的依赖），期间去泡杯茶。

### 3. 把 Gradle 的 JDK 改成 17（关键，不改会构建失败）

`File → Settings → Build, Execution, Deployment → Build Tools → Gradle`
→ **Gradle JDK** 选 `jdk-17`（路径 `D:\Program Files\Android\jdk-17`）。

AS 默认会用自带的 JBR（JDK 25），Gradle 9 跑不动，报错长这样：

```
The Java version used for the build is 25.0.4, which is incompatible with Gradle
```

### 4. 启动模拟器

`Tools → Device Manager`（或右侧边栏的手机图标）→ 找到 `Medium_Phone_API_37.0` → 点 ▶ 启动。

> 如果列表里没有：`Create Device` → 选 `Pixel 6` → 系统镜像选 `API 34` 以上、**x86_64**（不要选 ARM，会很卡）→ 完成。

### 5. 运行

顶部工具栏：设备下拉选 `Medium_Phone_API_37.0` → 目标选 `main.dart` → 点绿色 ▶（或 `Shift+F10`）。

第一次运行要编译，约 1~3 分钟；之后改代码热重载，回车即生效。

## 方式二：命令行（改代码时更快）

```bash
source /e/pingshu/env.sh
cd /e/pingshu

# 看有没有设备
flutter devices

# 没启动就先启动
flutter emulators --launch Medium_Phone_API_37.0

# 跑（debug 模式，支持热重载）
flutter run
```

热重载：改完代码在终端按 **r**；按 **R** 是热重启；按 **q** 退出。

### 只装 APK 不调试（最快，接近真实安装）

```bash
export PATH="/d/AndroidSdk/platform-tools:$PATH"
adb install -r build/app/outputs/flutter-apk/app-release.apk
adb shell am start -n cn.tingshu.app/.MainActivity
```

> 注意：`--split-per-abi` 产出的 `app-x86_64-release.apk` 才是模拟器用的架构，
> 但版本号会被改写（4001 之类），**只用于测试，不要用于发布**。

## 模拟器上能测什么、测不了什么

| 功能 | 模拟器 | 说明 |
|---|---|---|
| 界面、字号、按钮大小 | ✅ 能测 | 但真机手感不同，按钮大小最终要在手机上确认 |
| 页面跳转、返回栈 | ✅ 能测 | |
| 书架、回目、进度条 | ✅ 能测 | 需要先有书 |
| 缓存引擎（10G/淘汰/预取） | ⚠️ 半能测 | 逻辑能跑通，但真实速度、断网重连测不出来 |
| 睡眠定时、倍速 | ✅ 能测 | |
| 后台播放、锁屏控制 | ⚠️ 部分 | 模拟器有通知栏，但"锁屏"行为与真机不同 |
| 来电自动暂停 | ❌ 测不了 | 需要真机拨号 |
| 拔耳机自动暂停 | ❌ 测不了 | 模拟器没有耳机口 |
| 夸克网盘登录 | ⚠️ 能开页面 | WebView 能加载，但要输真实账号；建议真机做 |
| 夸克/B 站真实取流 | ⚠️ 不一定 | 模拟器 IP 是 NAT 出口，B 站风控可能直接拦（-412） |
| 性能/流畅度 | ❌ 测不了 | 模拟器是软件渲染，比真机慢得多 |
| 自动更新 | ⚠️ 需自建服务器 | 见 [06-自动更新](./06-自动更新与服务器配置.md) |

**结论**：模拟器适合快速验证"界面和交互对不对"，不适合验证"内容和网络能不能跑通"。
后者必须在老人的真机上做。

## 想在模拟器里测播书，怎么造数据

模拟器里没有网盘也没有书，最快的办法是**本地起一个 HTTP 服务器放 mp3**，然后把 App 的播放源指过去。

但当前版本只支持"夸克网盘"和"B 站"两个源，
所以更实际的做法是：

1. **测 UI/播放器**：临时把几个 mp3 放进模拟器，改 `CacheEngine` 读本地文件（改完记得改回来）；
2. **测完整链路**：直接用真机 + 真实夸克账号，这是唯一可靠的方式。

> 想加"本地文件夹"作为第三个源（方便调试，也能当离线书库用），
> 需要在 `lib/services/` 下新增一个 `LocalSource`，实现 `listBooks / detail / resolve` 三个方法，
> 再在 `AddPage` 里加一个入口。工作量约半天。

## 常用 adb 命令

```bash
export PATH="/d/AndroidSdk/platform-tools:$PATH"

adb devices                          # 看设备
adb install -r xxx.apk               # 覆盖安装
adb shell am force-stop cn.tingshu.app   # 强制停止
adb shell am start -n cn.tingshu.app/.MainActivity   # 启动
adb shell pm clear cn.tingshu.app    # 清空数据（相当于重装后首次打开）

adb exec-out screencap -p > shot.png # 截图到当前目录
adb shell input tap 540 1200         # 点击坐标（1080×2400 屏）
adb shell input text 'hello'         # 输入文字

adb logcat | grep -i flutter         # 看 Dart 日志
adb logcat -d -s AndroidRuntime:E    # 只看崩溃堆栈
```

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| AS 打开后没有 ▶ 运行按钮 | 没装 Flutter 插件，或打开的是 `android/` 目录 | 装插件，重新打开 `tingshu` 目录 |
| 构建报 Java 25 不兼容 | Gradle JDK 没改成 17 | 见上面第 3 步 |
| 构建卡在 `Downloading file from: https://github.com/media-kit/...` | libmpv jar 被清掉了 | 见 [02-环境与构建 §5](./02-环境与构建.md#flutter-clean-之后必须补的一步) |
| 模拟器启动极慢 / 黑屏 | 没开硬件加速（WHPX/HAXM） | BIOS 开 VT-x；Windows 功能里启用 Hyper-V 平台 |
| 应用装上但白屏 | 首次启动在初始化（最多 8 秒） | 等一下；仍白屏看 `adb logcat \| grep flutter` |
| 模拟器连不上我的本地服务器 | 模拟器 NAT / Windows 防火墙拦截 | 用 `adb reverse tcp:端口 tcp:端口`，然后 App 里填 `http://127.0.0.1:端口/...` |
