### P2b `The Java version used for the build is 25.0.4, which is incompatible with Gradle 8.14` / `failed due to Java/Gradle incompatibility`

**根因**：Flutter 默认使用 Android Studio 自带的 JBR（JDK 25），Gradle 8.x 不支持。
**注意**：`android/gradle.properties` 里的 `org.gradle.java.home` **会被 Flutter 传入的 JVM 参数覆盖，写了也没用**。
**处理**：
```bash
flutter config --jdk-dir D:/Jdk17     # 必须是全路径、无空格
```
并在 `android/gradle.properties` 保留一行（供直接跑 gradlew 时用）：
```
org.gradle.java.home=D:\\Jdk17
```

### P3 `'...ApplicationExtension.getDefaultConfig()'`（AGP 8 与 Flutter 插件不匹配）

完整报错：
```
Build file '...android/build.gradle.kts' line: 19
> 'com.android.build.api.dsl.ApplicationDefaultConfig com.android.build.api.dsl.ApplicationExtension.getDefaultConfig()'
```
**根因**：Flutter 3.50 的 gradle 插件按 AGP 9.3.1 的 API 编译，AGP 8.x 没有该方法。

**处理**：`android/settings.gradle.kts`：
```kotlin
id("com.android.application") version "9.3.1" apply false
id("org.jetbrains.kotlin.android") version "2.4.20" apply false
```

### P4 `'fun BaseAppModuleExtension.kotlinOptions(...)' is deprecated. Please migrate to the compilerOptions DSL.`

**根因**：AGP 9 默认 `android.newDsl=true`，旧 `kotlinOptions` 块被移除。
**处理**：`android/app/build.gradle.kts` 里把
```kotlin
android { kotlinOptions { jvmTarget = "17" } }
```
改成顶层：
```kotlin
import org.jetbrains.kotlin.gradle.dsl.JvmTarget

kotlin {
    compilerOptions {
        jvmTarget.set(JvmTarget.JVM_17)
    }
}
```

### P5 `Package ndk not found. Package 28.2.13676358 not found.` / `Android sdkmanager did not install NDK ...`

**根因**：Flutter 3.50 硬编码要求 NDK 28.2.13676358（即使项目无 native 代码），自动安装会失败。
**陷阱**：新版 SDK CLI 的包名格式是 **`ndk/28.2.13676358`（斜杠）**，用旧的 `ndk;28.2...`（分号）去 grep 会误判"仓库里没有"。
**处理**：
```bash
cd /d/AndroidSdk/cmdline-tools/latest/bin
./sdkmanager.bat --list 2>/dev/null | grep "ndk/28"     # 先确认有货
yes | ./sdkmanager.bat --install "ndk/28.2.13676358"    # 2.1GB
```

### P8 `Connection timed out: connect` + `Downloading file from: https://github.com/media-kit/...jar`

**根因**：`media_kit_libs_android_audio` 在**配置阶段**用 `new URL().openStream()` 同步下载 4 个 libmpv jar，无超时控制、无重试，GitHub Release 直连经常超时。
**处理**：手动下载到插件期望路径（注意 buildDir 被根脚本重定向到 `tingshu/build/<工程名>`）：
```bash
cd /e/pingshu/src
mkdir -p build/media_kit_libs_android_audio/v1.1.8
cd build/media_kit_libs_android_audio/v1.1.8
for a in arm64-v8a armeabi-v7a x86_64 x86; do
  curl -sL --retry 3 -O "https://github.com/media-kit/libmpv-android-audio-build/releases/download/v1.1.8/default-$a.jar" &
done; wait
md5sum *.jar
```
MD5 必须与下表一致（插件会校验，不一致会重下）：
```
6f4af754ae94da8cbb24655fd66c07ed  default-arm64-v8a.jar
d8d1ba181d3d6ecb341e1e8d87506e17  default-armeabi-v7a.jar
43ed7b0e6bdaa1a6ed2c1eee01f5e44a  default-x86_64.jar
a2acb148c02d02f0892047f5c6c4f964  default-x86.jar
```
⚠️ `flutter clean` 会删掉这些文件 → 清理后必须重放（见 [02-环境与构建 §5](./02-环境与构建.md#flutter-clean-之后必须补的一步)）。

### P9 `Unresolved reference 'registerForActivityResult'`（✅ 已解决 17:44）

完整报错：
```
e: MainActivity.kt:40:33 Unresolved reference 'registerForActivityResult'.
e: MainActivity.kt:42:9  Cannot infer type for value parameter 'result'.
e: MainActivity.kt:43:29 Unresolved reference 'data'.
e: MainActivity.kt:44:25 Unresolved reference 'resultCode'.
```
**根因**：`registerForActivityResult` 来自 `androidx.activity.ComponentActivity`，本项目未显式依赖 `androidx.activity`，Kotlin 编译期解析不到。
**处理（推荐）**：改用不依赖 androidx.activity 的经典写法，在 `MainActivity.kt` 中：

```kotlin
private const val REQ_QUARK_LOGIN = 1001
private var pendingLogin: MethodChannel.Result? = null

// 调用处
"login" -> {
    pendingLogin = result
    startActivityForResult(Intent(this, QuarkLoginActivity::class.java), REQ_QUARK_LOGIN)
}

// 重写
@Deprecated("Deprecated in Java")
override fun onActivityResult(requestCode: Int, resultCode: Int, data: Intent?) {
    super.onActivityResult(requestCode, resultCode, data)
    if (requestCode == REQ_QUARK_LOGIN) {
        val cookie = data?.getStringExtra("cookie")
        pendingLogin?.success(if (resultCode == android.app.Activity.RESULT_OK) cookie else null)
        pendingLogin = null
    }
}
```
同时删除 `import androidx.activity.result.contract.ActivityResultContracts` 和 `loginLauncher` 字段。

**备选方案**：在 `android/app/build.gradle.kts` 加 `implementation("androidx.activity:activity-ktx:1.9.3")`。不推荐——为一个 API 引入依赖，且版本需与 AGP 9 相容。

## 二、运行时类（预判，尚未真机验证）

### R1 播放页一直停在"正在准备这一回…"，进度不动

**可能原因**（按概率）：
1. 夸克直链 403 —— 检查 `QuarkApi.mediaHeaders` 是否被正确传给 `CacheEngine._download` 的 `options.headers`
2. Cookie 过期 —— 设置页"登录状态"会显示"未连接"，重新登录
3. B 站 `-412` 风控 —— 日志里会有 `-412`，等待 1~2 分钟后重试
**排查**：
```bash
adb logcat | grep -iE "flutter|quark|tingshu"
```

### R2 夸克登录后仍提示"未连接"

**原因**：`CookieManager.getCookie("https://pan.quark.cn")` 拿到的串里没有 `__puus` / `__pus`。
**说明**：用户在 WebView 里**没真正登录**（只打开了首页）。`QuarkLoginActivity.finishWithCookie()` 会判断这两个字段，缺失就返回 `RESULT_CANCELED`。
**排查**：`adb logcat | grep QuarkLogin`，或在 Dart 侧打印 cookie 长度（**不要打印内容**，含账号凭证）。

### R3 播完一回没有自动接下一回

**检查**：`TingPlayer._onCompleted()` 里 `hasNext` 判断；若 `book.chapters` 为空（夸克书未加载回目）则不会连播。
**根因常见于**：从"继续收听"直接进播放页，而该书回目从未加载过 → `open()` 时 `book.chapters` 为空 → 直接 return。
**修复方向**：`open()` 前确保 `chapters` 非空（`BookPage._ensureChapters()` 已有此逻辑，首页入口需补）。

### R4 缓存不增长 / 10G 上限没生效

**检查**：`/sdcard/Android/data/cn.tingshu.app/files/ting_audio/index.json` 是否存在且条目递增。
**注意**：`_usedBytes` 是内存计数，App 重启后由 `load()` 遍历索引重建，若索引损坏会归零（文件仍在，会在下次写入时被覆盖）。

## 五、已修复的运行时问题（真机验收第一轮）

### R5 退出播放页后点"继续收听"从头开始

**根因三层叠加**：
1. `open()` 无条件重新加载，不判断"是不是正在放同一回"；
2. 进度 5 秒才落盘一次，听 3 秒退出 → 库里还是 0；
3. `_mp.open()` 后立即 `seek` 会被 mpv **静默忽略**（文件头未解析完）。

**修复**：`open()` 加同源复用判断 + `PlayerPage.dispose()` 立即落盘 + `_seekAfterReady()` 等就绪再 seek。
**注意**：这三个必须同时修，只修任一处都会复现。
**代码**：`lib/player/ting_player.dart`（`open` / `_seekAfterReady`）、`lib/pages/player_page.dart`（`dispose`）

### R6 点书没反应、连点后弹出一堆播放页

**根因**：`await open()` 在下载完成前阻塞，期间无 UI 反馈；每次点击各挂一个 await，下载完成后一起 push。
**修复**：`unawaited(open())` + 立即 push + `_opening` 锁 + `open()` 的同源判断兜底。
**代码**：`lib/pages/book_page.dart`（`_play`）、`lib/pages/home_page.dart`（继续收听按钮）
**回归要点**：快速连点 5 次，应只出现 1 个播放页。

### R7 夸克登录页显示"下载夸克 App"而不是登录框

**根因**：WebView 用默认移动端 UA，夸克按 UA 分流到 App 下载引导页。
**修复**：`QuarkLoginActivity` 显式设置桌面版 Chrome UA + 开启缩放 + textZoom 115。
**代码**：`android/app/src/main/kotlin/cn/tingshu/app/QuarkLoginActivity.kt`
**遗留**：桌面版可能默认扫码登录，用户需手动切"验证码登录"。真机需复验。

## 六、通知栏 / 锁屏（2026-11-20 修复，真机与模拟器均已验证）

### R8 通知栏和锁屏完全没有播放控件（用户报的第一个问题）

**现象**：能正常出声，但下拉通知栏没有媒体卡片，锁屏也没有控件，只能解锁进 App 才能暂停。

**这不是一个原因，是三个叠加**。诊断命令（模拟器/真机都适用）：

```bash
adb shell dumpsys package cn.tingshu.app | grep -A1 POST_NOTIFICATIONS
adb shell dumpsys notification --noredact | grep -A2 cn.tingshu.app
adb shell dumpsys media_session | grep -A6 cn.tingshu.app
```

| # | 根因 | 当时实测值 | 说明 |
|---|---|---|---|
| 8a | **通知权限没申请** | `POST_NOTIFICATIONS: granted=false`，`importance=NONE` | Android 13+ 通知是运行时权限。我们只在 manifest 里声明了，从没在代码里申请，系统默认拒绝 → 通知完全不显示 |
| 8b | 媒体会话建得太晚 | — | `AudioService.init` 原来放在 `BootPage.initState`（runApp 之后）。会话建得晚，第一回播放没有通知，点通知也回不到 App |
| 8c | 没有 `AudioServiceWidget` 包裹 | — | audio_service 0.18 的硬性要求，缺了它通知点击回不到 Activity |

**修复**：

- `lib/main.dart`：`AudioService.init` 提到 `runApp` **之前**，并把整个 App 包进 `AudioServiceWidget`
- `lib/services/notify_permission.dart` + `MainActivity` 的 `tingshu/notify` 通道：
  `has` / `request` / `openSettings` 三个方法，走原生 `requestPermissions` +
  `onRequestPermissionsResult`（真正等用户点完再返回，不是"发起就返回"）
- `BootPage`：启动时 `requestOnce()`——没权限才申请，有权限立刻返回，不打扰
- 首页：没权限时顶部挂一条橙色提示"通知没打开，锁屏后不能暂停　去打开"，授权后永久消失
- 设置页：新增「通知栏显示播放控制」一行，已允许/未允许一目了然

**验证结果**（模拟器，2026-11-20）：

```

NotificationRecord(... channel=cn.tingshu.audio flags=NO_CLEAR|FOREGROUND_SERVICE
                    category=transport template=MediaStyle actions=2)
```

通知栏截图：封面、`第 1 回 001`、`兔子小蓝孩`、进度条、**上一回/−15s/暂停/+15s/下一回** 五个键全部正常。
锁屏截图：同样完整显示。


### R9 通知图标显示成白块 / 一片空白

**根因**：`androidNotificationIcon` 设的是 `mipmap/ic_launcher`（彩色图标）。
Android 通知栏的 smallIcon **必须是纯白剪影单色图**，系统会强制染色；
塞彩色图进去，多数机型渲染成白方块，部分机型直接不显示。

**修复**：新增 `res/drawable/ic_stat_tingshu.xml`（24dp 白色喇叭 + 两道声波矢量），
配置改成 `androidNotificationIcon: 'drawable/ic_stat_tingshu'`。

**判断标准**：通知左上角那个小图标，应该是**单色白喇叭**，不是一个方形色块。

### R10 改了 `androidNotificationOngoing: true` 之后编译报 `const_eval_throws_exception`

**报错**：`error - Evaluation of this constant expression throws an exception - lib\main.dart`，
指向 `const AudioServiceConfig(`，看不出具体是哪个参数错。

**根因**：audio_service 的构造里有断言：

```dart
assert(
  !androidNotificationOngoing || androidStopForegroundOnPause,
  'The androidNotificationOngoing will make no effect with androidStopForegroundOnPause set to false',
);
```

`ongoing: true` 必须配 `stopForegroundOnPause: true`。
但后者意味着**暂停就退出前台服务、通知随之消失**——对老人是倒退（暂停后想再点继续，通知没了）。

**结论**：保持 `androidStopForegroundOnPause: false` + `androidNotificationOngoing: false`。
通知在暂停后仍然存在，代价是可以被手动划掉（可接受，App 图标能重新进）。

### R11 通知里没有封面，只有灰块

**根因**：B 站返回的封面地址是 `//i0.hdslb.com/...`，**没有协议头**。
直接丢给系统会当相对路径，加载失败。

**修复**：`TingPlayer._coverUri()` 统一归一化——`//` 补 `https:`，`http://` 升 `https://`
（Android 9+ 默认禁止明文加载图片），非 http/https 一律返回 null 不传。

## 七、服务器部署踩的坑（Docker + nginx）

### P12 `duplicate default server for 0.0.0.0:5660`

**场景**：改主机 nginx 时先备份原配置，备份文件放在了 `/etc/nginx/sites-enabled/` 里。

**根因**：`/etc/nginx/sites-enabled/*.conf` **全是符号链接**，指向 `sites-available/`。
`cp -a` 备份会**保留链接属性**，于是 sites-enabled 里多出一个指向同一文件的链接；
而 `nginx.conf` 里的 include 是 `sites-enabled/*`（**通配，不看后缀**），
同一份配置被加载两次 → default_server 重复。

**连带风险**：临时文件也不能写在 `sites-enabled/` 里，同样会被 include。

**正确做法**（`tools/patch_nginx.py` 已按此实现）：
1. 备份到**目录外**：`cp -L <真实文件> /root/nginx-backup/xxx.<时间戳>`（`-L` 解引用）
2. 新内容先写 `/tmp/`，再 `cp` 覆盖 `sites-available/` 里的**真实文件**（不碰符号链接）
3. `nginx -t` 通过才 reload，不通过自动回滚

### P13 容器端口不要直接对外

容器绑 `127.0.0.1:8765`，外网经主机 nginx 的 `/tingshu/` 反代。
理由：复用 443 和泛域名证书，不用改阿里云安全组，也不用改 DNS。

## 八、网盘目录与推荐（2026-11-20 20:56）

### R12 夸克网盘里层级一深就"死掉"、一本书都出不来

**现象**：网盘里按「作者 / 书名 / 集数」层层套，进"添加评书"后列表里出现的
是作者名（或被当成的书），点进去回目是空的，界面像卡死。

**根因**：旧 `QuarkSource` 只往下看一层——子目录当书，再列一层当回目。
网盘根目录下第一层往往是**作者**，点进去全是目录、没有音频。

**修复**：递归拉平整棵树 → 复用 `NasScanner.scan()`（与 NAS 同一套规则）。
关键参数（`lib/services/quark/quark_source.dart`）：
```
_maxDepth = 8, _maxDirs = 800, _maxFiles = 30000, _maxDuration = 150s, 并发 4
```
单目录失败只跳过，不中断整次扫描。

**连带修的坑**：分卷目录名「上部/下部」会让书名退化成"上部"，一本书被拆成两本。
修法：标题只剩卷名时向上找父目录（跳过演员名、"评书"等噪音目录）。

**排查命令**（症状是"没有回目"时先看这里）：
```bash
adb logcat | grep -iE "quark|QuarkSource"
```
界面卡在转圈超过 90 秒，基本是目录数超限 → 让家属把评书根目录选得更靠下一点。

### R13 "推荐一本"推出了相声 / 推荐重复书目

**现象 1**：点推荐，播的是郭德纲单口相声。
**根因**：只搜关键词"评书"再按播放量排 —— 相声播放量比评书高一个数量级；
而且只校验了搜索结果的标题，详情页标题里才写着"单口相声"。

**修法**：按评书名家多路搜索 + `playCount` 排序 + **详情页二次校验**
（标题 + UP主 + 前 3 条回目名一起过黑名单）。
`NasScanner.knownActors` 里混着相声演员，那表只用于认目录作者，**不能当检索词**。

**现象 2**：刚听完《水浒传》，又推荐另一个 UP 主的《水浒传》。
**根因**：按书名原字符串比较，不同版本被当成不同的书。

**修法**：`TitleKey` 书名指纹 + `Library.heardKeys` 持久化"听过"清单
（听满 3 秒即记，最多 500 条，删书架也不清）。

**回归测试**：`flutter test test/title_key_test.dart`
改指纹规则前必须先让这 12 个用例通过，否则会出现"听过的书又被推一遍"。

### R14 设置页一行被超长文本撑坏（标题竖排 + 值溢出卡片）

**现象**：设置 → 评书文件夹，标题"评书文件夹"变成每行一个字竖着排，
右侧的文件夹名跑到卡片外面。
（真机截图见 `shots/` 与工作日志第 16 节）

**根因**：`BigRow` 的 Row 里，`value` 不是 flex 孩子 → 按固有宽度排布，
超长文本吃掉整行宽度；`Expanded(title)` 只剩几像素 → 中文按字换行。

**修法**（`lib/widgets/common.dart`）：
```dart
LayoutBuilder(builder: (context, c) {
  final maxValue = c.maxWidth * 0.45;          // 值最多 45%
  return Row(children: [
    Expanded(child: Text(title, maxLines: 2, overflow: ellipsis)),
    ConstrainedBox(
      constraints: BoxConstraints(maxWidth: maxValue),
      child: Text(value, maxLines: 1, overflow: ellipsis, textAlign: right),
    ),
  ]);
})
```
超长文件夹名在设置页再截断（保留头尾），完整名在选文件夹弹窗里看。

**回归测试**：`flutter test test/big_row_test.dart`
这条测试能直接报出溢出像素数（旧写法是 229px），比在模拟器上碰运气快得多。

**适用面**：任何"左标题右值"的行都该这么写。以后再有人加 `BigRow`，
不要把它改成不设 `maxLines` 的 `Text`。

## git push 失败：`Connection was aborted` / `schannel: server closed abruptly`

**现象**：`gh` 命令一切正常（`gh api user`、`gh release create` 都成功），
但 `git push` 一律失败，报：

```
fatal: unable to access 'https://github.com/popcalico/TingShu.git/':
  Recv failure: Connection was aborted
  schannel: server closed abruptly (missing close_notify)
```

换 `http.version=HTTP/1.1`、`http.sslBackend=openssl`、`http.postBuffer` 都无效。

**原因**：不是 git 配置问题，是**网络层只有 `api.github.com` 通，`github.com` 不通**。
实测：

```bash
curl -x http://127.0.0.1:3796 https://api.github.com/     # 200
curl -x http://127.0.0.1:3796 -I https://github.com/      # 000（超时）
curl --noproxy '*' -I https://github.com/                 # 000
```

`gh` 走 `api.github.com`，所以正常；`git push` 必须走 `github.com` 的 git 协议，所以失败。
`ssh.github.com:22` 和 `:443` 同样不通，换 SSH 也解决不了。

**处理**：

1. 等网络恢复/换网络（手机热点）后 `git push`——**同一台机器上有时能通**，`gh repo create --push`
   首次就成功了，说明是时段性干扰
2. 或者用 GitHub 网页/API 改文件（`api.github.com` 可达），但会与本地历史分叉，不推荐
3. 不要试图通过 `http.proxy=` 清空代理来"直连"——直连同样不通

**教训**：`gh` 能用不代表 `git` 能用，两者访问的是不同域名。
