### 为什么要有两个 Junction

Flutter 明确不支持**路径带空格**的 Android SDK（会破坏 NDK 工具链），而本机 SDK 和 JDK 都在 `D:\Program Files\` 下。用 NTFS Junction 造了两个无空格入口：

```powershell
New-Item -ItemType Junction -Path D:\AndroidSdk -Target "D:\Program Files\Android\android-sdk"
New-Item -ItemType Junction -Path D:\Jdk17      -Target "D:\Program Files\Android\jdk-17"
```

`D:\AndroidSdk` 在本次工作开始前**已存在**，`D:\Jdk17` 是本次新建。

## 3. 代理

本机（会话）已注入代理，`curl` / `git` / Gradle 默认会走：

```
http_proxy=http://127.0.0.1:5259
https_proxy=http://127.0.0.1:5259
```

`git config --global http.proxy` **未配置**，但环境变量已生效。需要持久化到 git 配置时：

```bash
git config --global http.proxy  http://127.0.0.1:5259
git config --global https.proxy http://127.0.0.1:5259
```

**实测效果**：不走代理时 GitHub Release 下载 3MB 需 17 秒且 Gradle 内置下载器会直接超时；走代理可稳定下载。

> 另注：本机 `reg.exe` 被安全策略列入程序黑名单，`flutter doctor` 的 "Windows Version" 检查项会崩，**不影响构建**，忽略即可。

## 4. 工具链版本约束（强约束，改动会直接构建失败）

| 组件 | 版本 | 为什么是这个版本 |
|---|---|---|
| Flutter | **3.50.1** (Dart 3.14.0) | 能用国内镜像下到的最新 stable；决定了下面三行 |
| Gradle | **9.5.0** | Flutter 3.50 最低要求 9.3.1；官方模板默认 9.5.0 |
| AGP | **9.3.1** | Flutter 3.50 的 gradle 插件按此 API 编译，8.x 会报 `getDefaultConfig()` 不存在 |
| Kotlin | **2.4.20** | 官方模板默认值，与 AGP 9 匹配 |
| JDK | **17** | Gradle 9 支持 17~25，但 Studio 自带的 25 实测跑不通；17 最稳 |
| compileSdk | 36 | 本机已装 platform 35/36/37 |
| minSdk | **24** (Android 7.0) | Flutter 3.50 默认值；也覆盖 2016 年后绝大多数在用机型 |
| NDK | **28.2.13676358** | Flutter 3.50 硬编码要求，即使无 native 代码也会校验 |

**版本来源不是猜的**，是读 Flutter SDK 里的常量表：
```bash

  "/d/Program Files/Android/flutter/packages/flutter_tools/lib/src/android/gradle_utils.dart"
```

## 5. 构建命令

```bash
source /e/pingshu/env.sh
cd /e/pingshu

flutter pub get
flutter analyze                 # 应为 0 error 0 warning
flutter build apk --debug       # 产物 build/app/outputs/flutter-apk/app-debug.apk
flutter build apk --release     # 正式包，用 android/key.properties 签名
```

首次构建约 5~8 分钟（含 Gradle 9.5 下载、依赖解析、Dart AOT）。增量构建约 30~60 秒。

### `flutter clean` 之后必须补的一步

`clean` 会删掉 `build/` 目录，其中包含**手动放置的 libmpv jar**（见 [04-故障排查 P8](./04-故障排查手册.md#p8)）。清理后重新构建前执行：

```bash
cd /e/pingshu
mkdir -p build/media_kit_libs_android_audio/v1.1.8
cd build/media_kit_libs_android_audio/v1.1.8
for a in arm64-v8a armeabi-v7a x86_64 x86; do
  curl -sL --retry 3 -O "https://github.com/media-kit/libmpv-android-audio-build/releases/download/v1.1.8/default-$a.jar" &
done; wait
md5sum *.jar
```

## 6. 签名

| 项 | 值 |
|---|---|
| keystore | `android/app/tingshu-release.jks` |
| 别名 | `tingshu` |
| storePassword / keyPassword | `见本机 android/key.properties（不入库）` |
| 有效期 | 10950 天（30 年） |
| 配置文件 | `android/key.properties`（在 `.gitignore` 中） |
| applicationId | `cn.tingshu.app` |

⚠️ **这个 keystore 一旦丢失，已装的 App 就无法覆盖升级**（只能卸载重装，书架和进度全丢）。请连同密码一起备份。

无 `key.properties` 时会自动回退 debug 签名（方便别人直接构建），逻辑在 `android/app/build.gradle.kts`。

## 7. 其他环境事实

- 本机 shell 是 Git Bash（POSIX sh），**不是** cmd/PowerShell。路径用 `/d/...` 或 `D:/...`。
- 需要 Windows 专属能力（注册表、服务、COM、GDI+）时才走 PowerShell 工具，不要在 Bash 里调 `powershell`。
- `reg.exe` 被黑名单拦截，涉及注册表读取的操作会失败，属预期。
- 磁盘：E 盘剩余约 1.4T，D 盘剩余约 365G，空间充足。
