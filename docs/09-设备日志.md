# 设备日志：采集、上报、回读

> 目的：老人在手机上点了什么、哪里卡住了，家属（和我）不用守着手机就能知道。
> 多台设备（爷爷的手机、奶奶的平板）各回各的，互不混淆。

---

## 1. 整体链路

```
App 内埋点
   ↓  AppLog.event/warn/error
本地文件  <应用私有目录>/app_logs/YYYY-MM-DD.jsonl（留 7 天）
   ↓  启动后 4 秒，把"游标之后"的条目打包
POST https://<服务器>/tingshu-log/report
   ↓  nginx 反代到本机 8790
python 服务（systemd: tingshu-log）
   ↓  按设备 + 日期落盘
/opt/tingshu-log/data/<deviceId>/YYYY-MM-DD.jsonl（留 30 天）
   ↓
设置 → 调试 → 设备日志 → 「服务器」标签（回读）
或 curl /export 拿纯文本喂给 AI
```

## 2. 客户端

### 2.1 日志服务 `lib/services/app_log.dart`

- **内存环形缓冲** 400 条：日志页实时看，不必每次读盘
- **落盘**：一天一个 `jsonl` 文件，只留 7 天，启动时清理
- **设备身份**：首次启动生成 `d` + 12 位十六进制，存 SharedPreferences；
  名字可在日志页改（"爷爷的手机"），没设就用机型
- **绝不拖累主流程**：init / 写入 / 读盘全部 try-catch 吞掉

### 2.2 埋点清单

| kind | 触发点 | 带的数据 |
|---|---|---|
| `app.start` | 每次冷启动 | 版本、versionCode、机型 |
| `play.start` | 一回真正开始播放 | 书名+回目、来源、第几回/总回数 |
| `play.pause` | 点暂停 | — |
| `play.next` / `play.prev` | 上一回/下一回 | — |
| `play.jump` | 回目列表点选 | 第几回 |
| `play.fail` | 播放失败 | 来源、回目、异常信息 |
| `book.add` | 加入书架 | 书名、来源、回数 |
| `book.remove` | 从书架删除 | 书名 |
| `search` | 搜索 | 关键词、本地命中数 |
| `log.report` | 上报完成/失败 | — |
| `crash.flutter` | Flutter 异常 | 异常 + 栈前 6 行 |
| `crash.platform` | 引擎层异常 | 同上 |

### 2.3 上报

- 时机：**只在启动后 4 秒**跑一次。不做定时轮询、不做后台服务——省电
- 游标：`ts_log_sent_at`（毫秒），只发比它新的；成功后前移
- 失败：静默，不弹提示、不重试；下次启动自然会补上
- 单次上限 800 条，超了取最新的那批

### 2.4 可视化

`设置 → 调试（只在测试版显示）→ 设备日志`

- **本机**：今天多少条、多少条错误；「只看错误」一键筛
- **服务器**：按设备列（自己的那台蓝框高亮），点进去看最近 300 条
- 底部：复制全部（纯文本，可直接粘给 AI）、手动上报、改设备名

## 3. 服务端

代码：`server/log_server.py`（Python 标准库，无第三方依赖）

| 接口 | 说明 |
|---|---|
| `POST /report` | 接收上报 |
| `GET /list` | 设备列表（名称、机型、版本、条数、最后时间） |
| `GET /tail?device=&limit=` | 某台设备最近 N 条 |
| `GET /export?device=` | 整台设备纯文本导出 |
| `GET /health` | 存活检查 |

所有接口要 `X-TS-Token`。

### 3.1 部署

```bash
# 1) 代码
scp server/log_server.py root@<服务器>:/opt/tingshu-log/

# 2) systemd（/etc/systemd/system/tingshu-log.service）
[Service]
Environment=TS_LOG_TOKEN=<和 App 里一致>
Environment=TS_LOG_PORT=8790
Environment=TS_LOG_DIR=/opt/tingshu-log/data
Environment=TS_LOG_KEEP_DAYS=30
ExecStart=/usr/bin/python3 /opt/tingshu-log/log_server.py
Restart=always

systemctl daemon-reload && systemctl enable tingshu-log --now

# 3) nginx（放在 ali.popcalico.top 的 443 server 里）
location /tingshu-log/ {
    proxy_pass http://127.0.0.1:8790/;
    proxy_set_header Host $host;
    client_max_body_size 16m;
}
```

### 3.2 直接取回来分析

```bash
TOKEN=<token>
BASE=https://<服务器>/tingshu-log

curl -s -H "X-TS-Token: $TOKEN" $BASE/list
curl -s -H "X-TS-Token: $TOKEN" "$BASE/export?device=d3746f4dd9d9a" > log.txt
```

`export` 出来的是纯文本（一行一条，带时间和分类），直接丢给 AI 就行。

## 4. 多设备怎么区分

- 每个安装实例一个 `deviceId`（首次启动生成，重装会变）
- 上报时带 `deviceName / model / manufacturer / sdk / versionName / versionCode`
- 服务器按 `deviceId` 建目录，`device.json` 记元信息
- 页面上自己那台会蓝框高亮；重装后设备号变了，会出现两条——属正常

**建议**：拿到手机后先在「设备日志」页把名字改掉（"爷爷的手机"），
否则列表里只能看到 `sdk_gphone64_x86_64` 这种型号。

## 5. 安全与隐私

- 日志里有**书名、播放时间、操作习惯**，不含账号密码、不含音频内容
- 接口靠单一 token 鉴权。token 写在代码里，而代码是公开仓库——
  **知道地址和 token 的人能读到日志**。这是当前方案的已知取舍
- 想更严一点，可以：① 换掉 token（改 App + 服务器两处）；
  ② 读取接口再要一个只有你知道的"分析口令"；③ 把 `/list` `/export`
  限制到特定 IP
- 服务器只留 30 天，超期自动删

## 6. 排查

| 现象 | 原因 |
|---|---|
| 日志页一直是"还没有日志" | 刚启动还没有埋点；正常播放一次就有了 |
| 「服务器」标签报"鉴权失败" | App 与服务器的 token 不一致 |
| 报"服务器上没有这个接口" | nginx 没配 `/tingshu-log/` |
| 上报一直失败但能上网 | 服务没起：`systemctl status tingshu-log` |
| 列表里出现重复设备 | 重装过（设备号变了），把旧的忽略即可 |
