## 2. 为什么是"子路径"而不是"子域名"

原计划用 `tingshu.popcalico.top`，实测发现 **DNS 没有做泛解析**：

```bash
nslookup tingshu.popcalico.top 114.114.114.114
→ Non-existent domain
```

而 `ali.popcalico.top` 有 A 记录（→ <你的服务器IP>），且证书是**泛域名证书**
（`*.popcalico.top`，Let's Encrypt，路径 `/etc/letsencrypt/live/wildcard-popcalico.top/`）。

所以选了**复用已有域名的子路径** `ali.popcalico.top/tingshu/`：
- 不用改阿里云 DNS（你我都得等解析生效）
- 不用新开安全组端口（443 已经在用）
- 证书本来就覆盖，无警告

**如果你以后想在阿里云 DNS 加一条泛解析 `*.popcalico.top → <你的服务器IP>`**，
就可以换成独立子域名，只需把 nginx 的 `server_name` 加一行、App 默认地址改一处，其他不用动。

**规矩：没有明确指示，只推 beta。** 老人手机不该被开发版骚扰。

## 4.1 日常发版：一条命令

```bash
cd tingshu

# 1. 改版本号（pubspec.yaml 的 build number 必须递增）
#    version: 1.1.7+11  →  version: 1.1.8+12
#                              ↑版本名    ↑versionCode

# 2. 发布（构建 + 校验 + 生成清单 + 上传，全自动）
./tools/publish.sh "修复了锁屏不能暂停的问题"           # → 推 beta（默认）
./tools/publish.sh "修复了锁屏不能暂停的问题" --stable  # → 推 standard
./tools/publish.sh "基线版：双通道" --both             # → 两条线同一个包
./tools/publish.sh "说明" --no-deploy                  # 只构建，不发布
```

脚本做的事：
1. `flutter build apk --release`
2. 用 `aapt2` 校验 APK 里的 versionCode 与 pubspec 一致（防误用 `--split-per-abi` 的旧产物）
3. 按目标通道生成 `server/version-beta.json` 和/或 `server/version.json`
4. SFTP 传到 `/opt/tingshu/www/`，确认容器在跑，并 curl 自测（含 `range` 是否 206）

手工核对：

```bash
curl -s https://ali.popcalico.top/tingshu/version-beta.json
curl -s https://ali.popcalico.top/tingshu/version.json
curl -sI -r 0-99 https://ali.popcalico.top/tingshu/tingshu.apk   # 必须 206
```

## 4.2 什么时候必须用 `--both`（基线对齐）

这条是踩过的坑，**新增任何"客户端新能力"时都要想一遍**。

**问题**：通道功能是 1.1.7 (code 11) 才有的。在此之前装出去的版本（code ≤ 10）里，
`version.json` 是写死的地址——它们**只会读标准线**。
如果双通道只有 beta 有（code 10 只在 `version-beta.json`），
那么手机上的旧版本永远看不到它，也就永远学不会"切通道"这件事。

**结论**：

| 场景 | 做法 |
|---|---|
| 改了客户端要新增/变更更新机制 | **必须 `--both`**：先让标准线也有这个能力，老设备才可能升上来 |
| beta 上验证稳定了，要转正 | `--both`：同一个包推两边，beta 设备 versionCode 相同，不会被判成降级 |
| 常规修 bug | 只推 beta |
| 确认要发给老人 | 只 `--stable`（beta 已先行验证过） |

**历史记录**：2026-11-20 20:0x 就是这么处理的——1.1.7 (code 11) 用 `--both` 同时进两条线，
标准线从 9 直接跳到 11，旧手机点一次"立即更新"就拿到了双通道能力。

## 5. ⚠️ 版本号的大坑（必须知道）

**`--split-per-abi` 会改写 versionCode**：

| 产物 | versionCode（pubspec 写 `1.0.2+3` 时） |
|---|---|
| `app-release.apk`（通用包） | **3** ← 只有这个能用于自动更新 |
| `app-arm64-v8a-release.apk` | 2003 |
| `app-armeabi-v7a-release.apk` | 1003 |
| `app-x86_64-release.apk` | 4003 |

后果：按通用包填 `versionCode: 3`，而手机装的是 arm64 包 2003 → App 永远认为"已是最新"；
反过来会被系统判为降级、直接拒绝安装。

**结论：只发通用包。** `publish.sh` 已内置校验，用错产物会直接报错退出。

## 6. 三个客户端关键实现（改代码时别破坏）

| 位置 | 实现 | 为什么 |
|---|---|---|
| `widgets/update_prompt.dart` | 一个弹窗走完 idle→下载→安装，**不跳页面** | 多一跳就多一次流失，老人独自在家点不了三四次 |
| `update_prompt.dart` | `didChangeAppLifecycleState(resumed)` 自动续上 | 从系统授权页返回后不能要求再点一次 |
| `update_service.dart` | `cleanupOldPacks()` 启动时清理旧包 | 每个包 36MB，不清理会堆到上百 MB |
| `update_service.dart` | `connectTimeout` **45 秒** + 重试 3 次 | 家用宽带跨网到阿里云，15 秒会超时（真机踩过） |
| `update_service.dart` | `download()` 支持 **Range 续传** | 36MB 一断网就从 0 重来，家里 wifi 很常见 |
| `update_service.dart` | `_explain()` 把 Dio 英文异常翻成中文 | 家属看不懂 `DioException [connection timeout]` |

断点续传的判定逻辑（别改坏）：
- 服务器返回 **206** → 追加写入
- 服务器返回 **200**（不支持 Range）→ 清空重写，**不能追加**，否则文件损坏

## 7. 故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 检查更新报"连不上" | 服务器挂了 / 域名解析挂了 | `curl -sI https://ali.popcalico.top/tingshu/version.json` |
| 一直提示"已是最新"，但服务器明明发了新版 | CDN/运营商缓存了 version.json；或用了 `--split-per-abi` 的包 | `curl` 加 `?t=时间戳` 看是否变化；检查产物 |
| 下载总是从头开始 | 服务器没返回 `Accept-Ranges: bytes` 或 Range 请求返回 200 | `curl -sI -r 0-99 <apk>` 必须是 206 |
| 下载完成但装不上 | 未知来源安装权限没开；或版本号比已装的低（降级） | 设置里引导授权；确认 versionCode 递增 |
| 上传了但内容没变 | 传到了错误目录 | 必须在 `/opt/tingshu/www/`，对应 URL 的 `/tingshu/` |
| 手机拿不到更新但浏览器能打开 | App 里手改过更新地址，指向了别处 | 设置 →「更新地址」→「恢复默认」 |

## 8. 安全提醒（自己看，别外传）

   （`TS_PWD` 默认值）。这个文件如果推到 GitHub 就等于把服务器交出去了。

   - 改密码，然后用环境变量传：`TS_PWD=新密码 python tools/deploy_server.py`

3. 更新目录不要开目录列表（容器 nginx 已 `autoindex off`）。
4. APK 走的是公网 HTTPS，任何人拿到链接都能下。这不敏感（只是安装包，签名验证能防篡改），
   但别在公开渠道贴地址。
